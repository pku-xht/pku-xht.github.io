# Legacy redirect Worker

This Worker matches only the generated public allowlist. Unmatched requests, non-GET/HEAD methods, login, administration, REST, private and unknown routes on `www.xht37.com` go to the original DNS origin via `fetch(request)`. On `xht37.com` they instead receive a non-cacheable 307 to the fixed `https://www.xht37.com` host with pathname and query preserved; the client retains the method and body. This relies on the client following redirects and on the old site's behavior and cookies at the www host. It must run as a zone route on the old hostnames, never as a Workers Custom Domain. Configure DNS proxying, TLS and zone routes only after verifying the real origin and www passthrough; deployment and DNS changes require separate authorization.

The generator reads the registered Markdown collection, its maintained resource map and public taxonomy slugs from the historical public snapshot. Category/tag URL forms are based on WordPress-style `/category/<slug>/` and `/tag/<slug>/` and must be checked against the actual old site before rollout. Only resources originating on the old host are mapped. Regenerate and check the file whenever these sources change. Query URLs are deliberately restricted to a single known `p` or `page_id` parameter, so all other query combinations pass through.

The 2026-10-31 production cutover is complete: both zone routes are attached and the checked-in `REDIRECT_STATUS` is `301`, with a one-hour cache lifetime. The initial non-cacheable 302 was verified before switching; a missing or different variable still falls back to 302. Encoded slashes, backslashes, controls and percent signs pass through to avoid ambiguous decoding. Worker development and preview URLs are disabled. Redirect Location has no fragment: browsers normally carry an incoming fragment forward. The server cannot see or remap fragments; old heading aliases are partial, and comment anchors depend on current approved comments and client loading. Static local tests do not prove Cloudflare routing, DNS, TLS, origin reachability or browser behavior; production evidence is in [the cutover record](../../migration/domain-visits-2026-10-31.md).

The two routes are managed in Cloudflare, while this repository's configuration deliberately declares no routes. For an authorized update, use `wrangler versions upload` followed by `wrangler versions deploy <version-id>@100%`, as documented in the root README. Ordinary `deploy` or `triggers deploy` can change routing and must not be used with this route-free configuration. Changing back to 302 does not retract a 301 already cached by a client.
