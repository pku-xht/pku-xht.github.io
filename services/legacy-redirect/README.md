# Legacy redirect Worker

This Worker matches only the generated public allowlist. Unmatched requests, non-GET/HEAD methods, login, administration, REST, private and unknown routes go to the original DNS origin via `fetch(request)`. It must run as a zone route on the old hostnames, never as a Workers Custom Domain. Configure DNS proxying, TLS and zone routes only after verifying the real origin and that passthrough works for both hostnames; deployment and DNS changes require separate authorization.

The generator reads the registered Markdown collection, its maintained resource map and public taxonomy slugs from the historical public snapshot. Category/tag URL forms are based on WordPress-style `/category/<slug>/` and `/tag/<slug>/` and must be checked against the actual old site before rollout. Only resources originating on the old host are mapped. Regenerate and check the file whenever these sources change. Query URLs are deliberately restricted to a single known `p` or `page_id` parameter, so all other query combinations pass through.

The default is a non-cacheable 302; set `REDIRECT_STATUS` to `301` only after verification. Encoded slashes, backslashes, controls and percent signs pass through to avoid ambiguous decoding. Worker development and preview URLs are disabled. Redirect Location has no fragment: browsers normally carry an incoming fragment forward. The server cannot see or remap fragments; old heading aliases are partial, and comment anchors depend on current approved comments and client loading. Static local tests do not prove Cloudflare routing, DNS, TLS, origin reachability or browser behavior.
