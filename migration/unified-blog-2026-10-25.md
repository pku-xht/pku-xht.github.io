- 117 条已公开评论及 43 条回复与所有后续评论统一存放并管理。新评论昵称必填、免注册，审核后才公开。

- 评论管理和编辑沿用原管理密码。表单支持浏览器的密码管理器；Chrome 是否提示保存/自动填入由本机设置决定，不能保证每次出现提示。

## 统一评论的数据边界

新增数据库迁移 `0002_unified_comments.sql` 为同一 `comments` 表增加安全 HTML 与公开作者网址，并保存最小导入批次/ID 哈希。离线工具从严格白名单的公开 YAML 生成 `services/blog-api/data/unified-comments.json` 和 `.sql`，保留昵称、全文、原 TeX、完整时间、作者链接、稳定 `wp-N` ID 和父子关系，已注册站内文章/资源链接映射为本地地址。

一次导入是一条 SQL 及其触发器事务；payload 完成后清空，批次与各 ID 的哈希保留。相同数据重复导入不改运行时状态，换批次也不复活已导入后删除的 ID；冲突哈希会回滚。最小 `legacy_parents` 兼容清单不再提供回复权限，只有同文实际存在且公开的父评论可被回复。

公开列表、待审/已公开/已拒绝管理队列和回复树均直接读取 D1。拒绝或删除包含所有同文回复后代，不分来源。旧 `#comment-N` 链接继续有效。页面不再序列化静态评论正文，避免拒绝/删除后被无脚本或加载失败时的旧兜底重新显示。

保留的公开 YAML/JSON 是不可覆写的导入与完整性证据，不是另一套可编辑评论库，不导出或回写待审评论、后续评论、邮箱、IP、账户或真实凭据。新提交只能是昵称和纯文本正文等允许字段，不能提交安全 HTML 或作者网址字段；客户端白名单重建已导入 HTML，本地 KaTeX 以 `trust:false` 处理评论公式。

## 文章编辑与发布链路

入口为 `/blog/posts/<ID>/exit/` 和 `/blog/pages/<ID>/exit/`，共覆盖 212 篇正式文档。生成页只有空编辑界面、固定后端和文档 ID，不含密码、私有数据或草稿。管理员登录后 GET `/v1/admin/articles/<ID>` 取得正式修订的源文本及 blob SHA；POST 仅提交 `{source,sha,request_id}`，不得修改文章身份或选择任意仓库路径。

候选分支为 `codex/article-edit/<UUID>`，只包含一篇已注册 Markdown 的修改。源 SHA 冲突时要求保留当前编辑并重新比较，不覆盖别处修改；同请求 ID 重试复用同一提交。主干上的受信工作流 `.github/workflows/publish-blog-edit.yml` 运行 `tools/publish_blog_edit.py`，检查候选身份、变更范围与基准，再执行正式构建与校验。它将源和生成页原子提交到 `main`，显式发起并验证对应 Pages build，最后更新候选提交的 `blog-publish` 状态。

候选提交、主干保存和 Pages 成功分开显示。浏览器通过 publication 接口和保存返回的 revision 轮询进度；本地模拟与单元测试不能当作这条远程链路已实际成功。工作流串行排队，不因新保存请求取消已有请求；候选分支不能向受权发布过程提供任意工作流或脚本。

新增 Worker secret 为 `GITHUB_EDIT_TOKEN`，仅目标 public 仓库的 Contents 读写、Commit statuses 只读和默认 Metadata 只读。既有 `ADMIN_TOKEN` 仍是界面管理密码，值不改变；它不是 GitHub 授权。工作流自身令牌仅 contents/statuses/pages write。所有真实 secret 及会话保存在后端或仓库外，候选分支同样属于公开仓库范围。

## 标准密码表单

账号为 `admin`，密码字段使用 `type="password"`、`autocomplete="current-password"`，账号字段使用 `autocomplete="username"`。认证成功后，在支持的浏览器调用凭据保存入口。浏览器可以自行保存、拒绝或自动填入；拒绝保存不影响本次管理。

网站不通过 Cookie、localStorage、sessionStorage 或 URL 保存密码，只保留当前页面内存。退出/离开会清除密码、源和管理内容，迟到响应不能恢复已清除会话。原 Windows DPAPI 备份继续位于公开仓库之外。

### 浏览器网络修复与验收

修复前，Chrome 能打开正式博客和新的静态页面，但评论接口域名 `xht37-blog-api.pku-xht-github-io.workers.dev` 的访问超时，页面显示可重试的加载失败。用户手动访问也复现；显式经现有本机 Clash 代理的 HTTPS 请求成功。用户后来提供的一条 Clash 连接源端口经只读核对属于 `ChatGPT.exe`，不能据此确认当时 Chrome 的代理路径。
