## 本地实现

首次实现曾在个人主页增加中英文全站 PV；用户随后更正位置，当前展示和计数仅覆盖博客阅读页。博客索引页省略文档 ID；文档页面同时累加全站和逐文 PV。重试使用同一加载 nonce，刷新页面计为新 PV。个人主页、管理页与编辑页不参与计数。

`features.yaml` 是唯一前端开关，生成器将配置直接写入博客页面。个人主页专用配置、统计脚本引用和展示节点已移除，博客生成器不再读取或改写个人主页；校验器拒绝个人主页重新带入统计节点或脚本。文章发布器不允许写根主页或已经移除的旧配置文件。

正式前端与 Worker 配置已改为启用；实际后端已部署，网页上线状态以本记录的发布核验为准。关闭时不发送 API 请求；缺少有效基线或请求失败时隐藏计数，不显示虚假零值。

独立的旧域名 Worker `xht37-legacy-redirect` 已生成 348 条明确公开路径：212 篇文档、4 个分类、91 个标签、41 个旧域资源；另有 212 个 `p`／`page_id` 查询映射。匹配的 GET/HEAD 最初以不缓存的 302 验证，正式配置现为缓存一小时的 301。`www` 的其余请求保持原请求回源；新增裸域名的其余请求以不缓存的 307 跳到固定旧 `www` 主机，保留方法、路径和查询，避免依赖原服务器的裸域名证书。后台、登录、REST、未匹配和私密路径不会被统一跳到公开新站。编码分隔符、控制字符和双重编码歧义不匹配；关闭 Worker 开发和预览域名。代表分类、标签地址已在旧站实测可达，未穷举所有旧 taxonomy URL。

## 正式切换核对顺序

1. 按已确认的 Cloudflare 方案核对完整现有记录及证书、原站回源、回退条件。公共 DNS 查询不能代替管理端的完整记录清单。
2. 验证公开路由白名单；后台、登录、私密及未知请求不能因通配跳转丢失，也不能把私密 URL 或内容放入公开映射。
3. 在短窗口取得最新完整逐文 PV 与独立全站 PV，在仓外保存并 dry-run 校验；旧访客数另存，不冒充 PV。
4. 导入完整基线，安排前后端启用与域名跳转，核对精确发布状态。
5. 实测两个旧域名根、代表公开链接、资源、后台登录和私密可见性，再核对全站与逐文增量。

DNS 缓存与旧站仍在处理的请求可能产生小偏差；当前不承诺两个系统严格同时完成事务。

首次打开 Cloudflare 控制台时，浏览器读取持续超时；随后浏览器工具报告无法可靠确认当前网页地址，停止了当轮控制，没有绕过该限制或改用其他浏览器控制方式。后续用户继续后已恢复 Chrome 读取，确认 Cloudflare 登录正常。
