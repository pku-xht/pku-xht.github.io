# 迁移与核验流程

## 1. 固定公开来源和范围

- 新增迁移或刷新原站快照时，从 `migration/README.md` 读取本批选择，核对原站匿名接口中的状态、密码保护标记、分类、文章 ID 唯一性和总数；接口重写问题与已验证入口同样记录在那里。已有 Markdown 的日常维护直接核对正式源与成员清单，无需重新访问旧站。
- 保存新增或刷新的快照前核实公开性。不要登录后台后再过滤私密导出；非公开内容的处理位置与授权边界以根 `AGENTS.md` 为准。
- 正文快照、图片来源与哈希保存在 `migration/sources/`。新批次先获得确定的范围，不能因接口能返回更多内容而自动扩大本批。
- 已授权评论迁移时，只请求正式公开集合所关联的已批准评论，保存前白名单保留原本公开的字段，不保存邮箱、IP、用户代理或账户资料。匿名 API 无法列举某种类型时，核对既定公开文的前台评论容器，不通过登录绕过边界。

## 2. 保留内容并生成静态页

- 新迁内容先转为独立 Markdown 与 YAML 元数据并登记正式成员清单；已有文章直接维护正式源。原快照仅保留作校验，导入工具不得覆盖已经存在的维护源。
- 正文、原始发布日期、原始修改日期和代码内容保持可追溯。列表摘要可单独维护，不将候选主题标签冒充原站已有标签。
- 生成器移除插件注入的动态 Visits 计数，保留正文中的所有知识点、表格和插图；只对排版所需的 HTML、标题层级和链接做适配。
- 公式采用构建期排版。兼容性变换及原始 TeX 的保留方法以根 `README.md` 为准；公式失败应修复具体兼容问题，不能静默删掉公式或正文。
- 图片使用公开原图，记录原 URL 和校验值，保留格式、动画和应有署名。本批已迁文章间的旧站链接改为新地址，其余链接保留原目标。
- 页面、构建工具、校验器与正式命令按根 `README.md` 的入口维护，不手改生成的文章 HTML。
- 历史公开评论保留原昵称、完整时间、父子关系和安全化后的完整正文；原始 HTML 另存校验。友链保留原名称、URL 和顺序；标签云及静态标签页从真实文章标签派生。
- 新评论与 Visits 按当前批次选择实现。默认关闭与缺失后端配置应当明确不可用，不能显示虚假提交成功；未来数据继承、后端部署和流量切换是独立状态，不能因代码测试通过而自动启用。

## 3. 完整性与浏览器核验

- 执行正式生成和独立校验命令。日常检查以正式 Markdown 源为准；迁移与需要复核原文时另运行原快照对照模式。正文比较恢复原始 TeX，排除访问计数与排版空白；代码逐字符比较，并核对图片、表格、标题、日期、本地链接和字体资源。
- 浏览器检查首页摘要、搜索、空结果、清空、归档、代表文章和相邻文章跳转。覆盖长公式、代码、长表格、多级目录和 GIF 等本批实际内容；窄屏确认溢出被限制在对应块内。
- 可用同源 iframe 的真实窄屏视口检查 CSS 媒体查询；它是浏览器布局检查，不能称作手机实机验收。关闭脚本后至少检查静态正文和公式可读。
- 只有实际观察或独立比较支持的项目才记录为通过；界面成功提示不能替代最终效果。必要的工具读回限制写入验证记录，不推断成产品故障或已通过。
- 涉及评论后端时验证提交、待审隔离、管理员审核后可见、回复归属及基础频控；涉及统计时验证关闭零写入、幂等、并发增量和独立旧基线。SQLite 适配与本地浏览器通过不能代替实际 Cloudflare D1 部署验证。

## 4. 更新状态并交付

- 同步 `migration/README.md` 中本批的实际状态和验证证据；批次映射由生成器记录。设计选择变更时同步 `DESIGN.md`，不把候选原型当成正式验收。
- 检查与当前实现对应的文档、技能引用和命令，按根 `AGENTS.md` 的本地提交与发布边界完成交付。
